# DemandHub 发布经验总结 v1.0

> 沉淀于 2026-10-15，基于历次 TEST 环境发布实践整理。每次发版按此 SOP 执行，避免重复踩坑。

---

## 一、三端发布形态

| 端 | 发布方式 | 访问路径 | 说明 |
|---|---|---|---|
| H5 提报端 | h5pub package → upload → release（应用 demand-hub, id=54） | `https://fenhangtest.clearmindz.top/h5-preview/demand-hub/` | 预览地址；正式路由需在平台手动点「发布」 |
| 后端 API | h5pub backend build-remote → deploy-test | `/demandhub-api` | 镜像含管理后台产物 |
| 管理后台 | 不单独发布，产物打进后端镜像 | `https://fenhangtest.clearmindz.top/demandhub-api/admin/` | 前端用 hash 路由，同容器同域托管 |

## 二、标准发布流程（严格串行）

### 步骤 1：本地全量验证

```powershell
# 后端
cd server
.venv\Scripts\python.exe -m pytest --tb=short -q   # 期望 453+ 全绿
.venv\Scripts\python.exe -m ruff check .              # 期望无 lint 错误

# 前端
cd frontend\h5
npm run vitest -- --run                               # 期望全绿
npm run build                                         # 期望构建成功
```

### 步骤 2：Git 提交推送

```powershell
# 中文 commit message 用临时文件（PowerShell heredoc 不支持）
git add <具体文件>
git commit -F commit_msg.txt
git push origin main
# 代理失败时绕行：
git -c http.https://github.com/.proxy= push origin main
```

### 步骤 3：h5pub 认证

- Token 有效期 7 天，过期须用户手动登录
- 助手可用以下命令弹出桌面独立终端窗口供用户输入密码：

```powershell
Start-Process powershell -ArgumentList '-NoExit','-Command','h5pub auth login --username liuquan'
```

- 验证认证状态：

```powershell
h5pub --output json --no-input --context test auth status
```

### 步骤 4：H5 发布

```powershell
cd frontend\h5
h5pub --output json --no-input --context test h5 publish-test demand-hub `
    --source . --create-if-missing `
    --build-command "powershell -NoProfile -Command npm run build -- --mode deploy"
```

**注意**：
- `--build-command` 必须用 PowerShell 垫片（见避坑清单第 1 条）
- `--mode deploy` 必须显式传递（package.json 无 build:deploy 脚本，vite.config.ts 无 mode 逻辑，全靠 `.env.deploy`）

### 步骤 5：后端远程构建 + 部署

**前置检查（2026-10-21 起强制，见避坑清单第 11 条）**：本次待发布改动若包含 `frontend/admin/` 源码，必须**先**重新构建 admin 并整体拷贝（保留目录结构），否则镜像里仍是旧前端：
```powershell
cd frontend\admin; npm run build; cd ..\..
Copy-Item frontend\admin\dist server\frontend\admin\dist -Recurse -Force
```

```powershell
# 构建前：临时移出 server/.env（见避坑清单第 2 条）
Move-Item server\.env "$env:TEMP\demandhub_server_env.bak" -Force

# 远程构建 + 部署（约 20 分钟）
h5pub --output json --no-input --context test backend build-remote demandhub-api `
    --source server --confirm-source-processing --create-if-missing --deploy-test

# 构建后：立即恢复 .env
Move-Item "$env:TEMP\demandhub_server_env.bak" server\.env -Force
```

**注意**：`.env` 移出期间不要重启本地 API 服务（重启会因读不到 .env 起不来）。

### 步骤 6：环境变量增量更新（仅配置有变时）

```powershell
# 通过 stdin 注入，敏感值不回显
h5pub --output json --no-input --context test backend configure demandhub-api --from-env-file -
```

### 步骤 7：部署验证

```powershell
# 三端地址可达性
# H5: https://fenhangtest.clearmindz.top/h5-preview/demand-hub/
# 管理后台: https://fenhangtest.clearmindz.top/demandhub-api/admin/
# 后端 API: https://fenhangtest.clearmindz.top/demandhub-api/
# 若本次含 admin 改动：线上 admin index.html 引用的 JS 哈希必须与本地新构建产物一致（见避坑清单第 11 条）

# 数据库迁移完整性（期望 33 张表 = 0001~0010 全量迁移完成）
h5pub --output json --no-input --context test database overview demandhub_api_runtime
```

### 步骤 8：部署完成汇报（固定模板）

每次部署完成后，必须向用户汇报以下三项：

1. **H5 小程序端登录地址**：https://fenhangtest.clearmindz.top/h5-preview/demand-hub/
2. **管理后台登录地址 + 默认账号**：
   - 地址：https://fenhangtest.clearmindz.top/demandhub-api/admin/
   - 账号：`admin`
   - 密码：不落文档（首登强制改密；当前有效密码由使用者自行保管或向运维索取，严禁写入任何会提交 git 的文件——2026-10-17 教训：真实密码曾误入库推送 GitHub，已轮换作废）
3. **平台发布提醒**：预览版发好后，需要到 H5 发布平台手动点「发布」把正式路由切到新版（PROD 级动作，只能人工操作）

## 三、避坑清单

### 1. Windows npm 解析失败（2026-10-15 踩坑）

**现象**：h5pub 默认构建命令报 `local tool not found: npm`

**根因**：Windows 上 npm 只有 `npm.cmd`（CMD 垫片），无 `npm.exe`，h5pub 直接 spawn `npm` 找不到可执行文件。`cmd /c` 被 CLI 安全拦截不可用。

**解决**：必须传 `--build-command`：
```
--build-command "powershell -NoProfile -Command npm run build -- --mode deploy"
```

### 2. server/.env 源码快照被拦截（2026-10-15 踩坑）

**现象**：后端远程构建报 `sensitive file is not allowed: .env`

**根因**：h5pub 源码快照不认 gitignore / dockerignore，敏感文件校验直接拒绝。`.dockerignore` 早已排除 `.env`，但快照仍会带上。

**解决**：构建前临时移出，构建后立即恢复：
```powershell
Move-Item server\.env "$env:TEMP\demandhub_server_env.bak" -Force
# ... 构建命令 ...
Move-Item "$env:TEMP\demandhub_server_env.bak" server\.env -Force
```

### 3. JWT_SECRET 过短导致容器启动崩溃（2026-10-14 踩坑）

**现象**：容器 exit 1，container-logs 只见 alembic 迁移警告，无 stderr traceback。

**根因**：`config.py` 中 `jwt_secret: str = Field(min_length=32)`，短值导致 uvicorn 启动期 pydantic 校验直接崩溃。平台不采集 stderr traceback，日志只见迁移警告（误导排查方向）。

**排障范式**：
1. `database overview` 数表（33 张 = 迁移全量完成）→ 排除迁移失败
2. 本地模拟启动 → 排除代码问题
3. 短值复现 → 锁定根因
4. 修复：`backend configure --from-env-file -` 经 stdin 注入 64 位随机值

### 4. 管理后台 /admin 404（2026-10-15 踩坑，两层原因）

**第一层**：admin 构建产物不在 server 构建上下文
- 修复：本地构建 `frontend/admin` 后拷贝 `dist` 到 `server/frontend/admin/dist`，Dockerfile 加 `COPY frontend/admin/dist /frontend/admin/dist`

**第二层**：`app.mount("/admin")` 无前缀
- 根因：Kong 网关不剥前缀转发，API 路由全以 `/demandhub-api` 注册（`APIRouter(prefix=settings.api_root_path)`），静态挂载挂 `/admin` 会因路径不匹配 404
- 修复：`app.mount(f"{settings.api_root_path}/admin", StaticFiles(...))`（提交 a1ab88b）
- 本地直连 `:8000/admin/` 能通掩盖了该问题（本地无网关前缀）

### 5. h5pub token 过期需手动介入

**现象**：所有远端操作返回 UNAUTHORIZED

**解决**：助手用 `Start-Process` 弹出桌面独立终端窗口，用户直接输密码。后台 shell 任务用户无法交互，日志恒空。

### 6. deploy 失败后误重建镜像

**现象**：deploy 失败后误以为要重新 build

**解决**：deploy 失败通常自动回滚，相同镜像直接重新 deploy 即可（平台侧瞬时故障也如此，如 `exec /usr/bin/sh: operation not permitted` 无容器日志的 case）。

### 7. PowerShell heredoc 不支持

**现象**：git commit message 含中文时无法用 heredoc

**解决**：写入临时文件 + `git commit -F`（文件须 UTF-8 编码）。

### 9. admin 产物平铺拷贝导致线上白屏（2026-10-16 踩坑）

**现象**：管理后台 `/admin/` 打开空白，index.html 返回 200 但引用的 `./assets/*.js|css` 全部 404。

**根因**：把 `frontend/admin/dist` 拷贝到 `server/frontend/admin/dist` 时把 `assets/` 子目录里的文件**平铺**拷到了根目录，目录结构丢失——index.html 仍在（页面 200、标题正常），但 `assets/` 不存在（资源 404、白屏）。只验证 index.html 200 无法发现此问题，必须验证资源文件可达。

**解决**：删掉错误拷贝，用 `Copy-Item frontend\admin\dist server\frontend\admin\dist -Recurse` 保留目录结构整体拷贝，重新构建部署后端。

### 10. build-remote 返回 UNCERTAIN_OUTCOME（CLI 本地超时）

**现象**：后端构建部署命令报 `UNCERTAIN_OUTCOME: request timed out after it may have reached the platform`。

**根因**：CLI 本地等待超时，平台侧操作可能实际已完成（2026-10-16 出现两次：一次实际成功、一次操作卡在 deploy-test:RUNNING 显示不更新但实际成功）。

**解决**：按顺序对账：`operation list` 查状态 → `operation show <operation-id>` 看细节 → 仍不明则 `operation resume <operation-id>` 恢复对账（服务端幂等记录会给出最终结果）。切勿盲目重试原命令。

### 11. 管理后台源码改了但镜像里还是旧前端（2026-10-21 踩坑）

**现象**：后端发布成功后，管理后台界面上看不到本次的前端改动（需求列表「含草稿」、需求详情、AI 对话原文显示优化等）。线上 admin JS 哈希与上一版一模一样（如 `index-DnJLDXZP.js`、字节数不变）。

**根因**：镜像里的管理后台是 `server/frontend/admin/dist` 这份**本地拷贝**（Dockerfile `COPY frontend/admin/dist /frontend/admin/dist`），它只在「本地重新构建 frontend/admin 并整体拷贝」后才会更新。本次 admin 源码已随 commit 改动，但发布流程误判「admin 无改动」跳过了构建+拷贝，导致镜像打包的还是旧产物。**代码在仓库里 ≠ 前端产物在镜像里。**

**解决**：重新构建 admin 并整体拷贝（保留目录结构，见第 9 条），再重发后端镜像：
```powershell
cd frontend\admin; npm run build; cd ..\..
Copy-Item frontend\admin\dist server\frontend\admin\dist -Recurse -Force
# 再执行步骤 5 后端远程构建 + 部署
```

**防再犯（强制检查项，不许靠人工记忆）**：每次后端发布前，必须执行以下判断，任一命中就要先走上面的构建+拷贝：
```powershell
git log --oneline -1 -- frontend/admin/   # 最近一次 admin 改动的提交
git diff --stat HEAD -- frontend/admin/   # 工作区是否有未提交 admin 改动
# 且对比 server/frontend/admin/dist 的构建时间是否晚于最新 admin 源码改动时间
```
验证环节加一道：发布后线上 admin index.html 里的 JS 哈希**必须与本地新构建产物一致**，不一致即说明拷的是旧货（只验 200 不够）。
