# DemandHub 运维部署文档

适用版本：v1.0（阶段 8 交付）。本文档覆盖：全新部署、升级回滚、配置说明、常见问题。

## 1. 架构总览

```
浏览器
  └─ :80  → frontend(Nginx) → / → PC 端静态资源
                            → /h5/ → H5 端静态资源（P5 起同域，原 :81 已合并）
                │ /api 反代
                ▼
        gateway :8080（鉴权/路由 StripPrefix）
          ├─ /api/system/**       → system :8081（认证/用户/组织/授权）
          ├─ /api/demand/**       → demand :8082（需求主流程/看板/报表）
          ├─ /api/notification/** → notification :8083（站内信/企微推送）
          └─ /api/agent/**        → agent :8084（AI 提报启发/处理辅助/RAG）

中间件：MySQL 8.0 / Redis 7 / MinIO / Nacos / RocketMQ(namesrv+broker)
```

一套 `deploy/docker-compose.prod.yml` 拉起全部 12 个容器（6 中间件 + 5 后端 + 1 前端）。

## 2. 前置条件

- Docker Engine 24+（含 compose 插件），内存 ≥ 8G，磁盘 ≥ 20G
- 宿主机端口空闲：80、8080、3307、9000、9001、8848、9848
- 镜像构建需访问公网（Maven/npm 依赖）；已配置构建缓存挂载，二次构建显著加速

## 3. 首次部署

```bash
git clone <repo> && cd DemandHub
docker compose -f deploy/docker-compose.prod.yml up -d --build
```

- 首次构建约 15~30 分钟（5 个后端 Maven 构建 + 2 个前端 npm 构建）
- MySQL 首次启动自动按序执行 `deploy/mysql/init/01~05`（全部幂等，重放安全）
- MinIO bucket `demandhub` 由 demand 模块启动时自动创建，无需手动

验证：

```bash
docker compose -f deploy/docker-compose.prod.yml ps        # 全部 Up
curl http://localhost:8080/api/system/ping                 # 网关→system 联通
curl "http://localhost:8080/api/system/auth/callback?code=mock-u_admin_001"   # 登录发证
浏览器访问 http://localhost/（PC）  http://localhost/h5/（H5）
```

Mock 账号（企微 Mock 静默登录 code=mock-{userId}）：
u_admin_001(ADMIN)、u_exec_001(EXECUTIVE)、u_mgr_tech(科技线经理)、
u_handler_a1/u_handler_b1(HANDLER)、u_reporter_1/u_reporter_2(REPORTER)。

## 4. 升级与回滚

### 升级（滚动替换单模块）

```bash
git pull
docker compose -f deploy/docker-compose.prod.yml up -d --build demand   # 只重建 demand
docker compose -f deploy/docker-compose.prod.yml up -d --build frontend # 只重建前端
```

### 回滚

```bash
git checkout <上一个稳定 commit>
docker compose -f deploy/docker-compose.prod.yml up -d --build <service>
```

- 数据卷独立于镜像（mysql-data / redis-data / minio-data / rocketmq-*-data），回滚代码不丢数据
- DDL 变更只增不减（IF NOT EXISTS 幂等），旧代码可在新库结构上运行；如需整库回退，先备份：

```bash
docker exec demandhub-prod-mysql mysqldump -uroot -pdemandhub123 demandhub > backup_$(date +%F).sql
```

### 完全重置（慎用）

```bash
docker compose -f deploy/docker-compose.prod.yml down -v   # -v 连数据卷一起删
docker compose -f deploy/docker-compose.prod.yml up -d     # 重新初始化
```

## 5. 配置说明

后端通过环境变量注入（compose 已配默认值，生产按需覆盖）：

| 变量 | 默认 | 说明 |
|---|---|---|
| MYSQL_HOST/PORT/DB/USER/PASSWORD | mysql/3306/demandhub/root/*** | 数据源 |
| REDIS_HOST/PORT | redis/6379 | 会话/缓存/分布式锁 |
| ROCKETMQ_NAMESRV | rocketmq-namesrv:9876 | MQ |
| MINIO_ENDPOINT/ACCESS_KEY/SECRET_KEY/BUCKET | http://minio:9000 ... | 附件/报表存储（仅 demand） |
| JWT_SECRET |  compose 内占位值 | 网关与 system 必须一致；生产必改 |
| SYSTEM_URI/DEMAND_URI/NOTIFICATION_URI/AGENT_URI | http://<service>:<port> | 网关路由目标（仅 gateway） |

外部接口开关（一期无真实凭证，保持 Mock；拿到凭证后新增真实实现并置 false）：

```
demandhub.integration.wecom.mock=true           # 企微 OAuth（system）
demandhub.integration.pcenter.mock=true         # 权限中心主数据（system）
demandhub.integration.wecom-message.mock=true   # 企微消息推送（notification）
demandhub.integration.llm.mock=true             # 大模型平台（agent）
```

## 6. 常见问题

**Q1 RocketMQ broker 起不来 / 消费全挂（StoreUtil NPE）**
cgroup v2 宿主机上 broker 容器内 JDK8 读容器 metrics 会 NPE。compose 已注入
`JAVA_OPT=-XX:-UseContainerSupport`，勿删。

**Q1b broker 反复重启，日志报 `Permission denied: /home/rocketmq/store/lock`**
镜像内 `/home/rocketmq/store` 目录不存在，命名卷首次挂载由 Docker 以 root 创建，
rocketmq 用户无写权限。compose 已为 broker 配置 `user: root`，勿删；
若曾以非 root 启动过，需删除旧卷重建：`docker volume rm demandhub-prod_rocketmq-broker-data`。

**Q2 后端连不上 RocketMQ broker**
broker 注册地址必须是容器网络可达的名字。prod 用 `deploy/rocketmq/broker-prod.conf`
（brokerIP1=rocketmq-broker）；本地开发用 `broker.conf`（brokerIP1=127.0.0.1），两文件勿混用。

**Q3 中文入库乱码**
MySQL 必须 utf8mb4。init 脚本首行均带 `SET NAMES utf8mb4`，容器启动参数
`--character-set-server=utf8mb4`。存量乱码修复见项目 memory（CONVERT(BINARY CONVERT ... latin1) 方案）。

**Q4 登录后频繁 401**
Redis 会话先于 JWT 过期属预期，前端自动用 refreshToken 换新；若 Redis 重启则全员需重新登录。

**Q5 看板数据与列表页对不上**
看板走 `demand_stat_daily` 预聚合表，StatDailyJob 每 5 分钟增量刷新；5 分钟内差异属预期。
手动触发：重启 demand 模块或等下个刷新周期。

**Q6 报表导出任务一直 PENDING**
确认 MinIO 容器健康且 demand 模块日志无 bucket 异常；导出为异步线程池执行，大报表需等待。

**Q7 通知未送达**
链路：demand 发 MQ → notification 消费写库 → 企微 Mock 推送。依次查：
`docker logs demandhub-prod-rocketmq-broker`、`docker logs demandhub-prod-notification`、
notification 表数据。企微 Mock 模式 FAIL 会走 RocketMQ 延迟重试（指数退避，上限 5 次）。

**Q8 大模型接口 1401 降级**
`agent` 模块运行期开关：`POST /api/agent/admin/llm/switch`（ADMIN）。Mock 关闭时前端收到
1401 应提示降级；真实平台不可用时同样走该降级路径。

**Q9 前端 502 / API 无响应**
按链路查：`docker logs demandhub-prod-frontend` → `gateway` → 目标模块。
网关路由目标在容器网络按服务名解析，确认 5 个后端容器全部 Up。

**Q10 授权变更多久生效**
数据范围缓存 Redis 60 秒；授权接口会刷新会话，最迟 1 分钟内生效（FR-M1-03 验收口径）。

## 7. 测试环境（P6 test profile）

`deploy/docker-compose.test.yml` 拉起独立测试栈（project `demandhub-test`），与 dev 栈并存互不干扰：
独立卷、独立宿主端口，代码从当前源码构建，渠道 SSO 走 **test profile**——`CHANNEL_SSO_MOCK=false`，
内置 Mock 端点不暴露，verify 回源目标由环境变量注入。

### 7.1 与 dev / prod 的差异

| 项 | dev（本地 spring-boot:run） | test（本章节） | prod |
|---|---|---|---|
| 渠道 SSO 配置来源 | demand_channel.config_json（指向内置 Mock） | **CHANNEL_LS_\* 环境变量**（优先于 config_json） | 同 test，换真实值 |
| CHANNEL_SSO_MOCK | true | false | false |
| verify 回源 | 内置 Mock（system:8081） | contract-mock 容器（契约级，严格验签） | 创金零售真实地址 |
| app_secret | 库内 ENC 密文 | 环境变量明文注入（仅内存使用） | 环境变量注入（保密管理） |

`ChannelSsoTicketVerifier` 仅当 `CHANNEL_LS_BASE_URL/APP_KEY/APP_SECRET` 三项齐备时启用 env 覆盖，
因此 dev 不设置这些变量即完全不受影响；拿到创金零售真实凭证后无需改库、无需重建镜像，改环境变量重启即可。

### 7.2 启动

```bash

docker compose -f deploy/docker-compose.test.yml ps     # 13 个容器全部 Up/healthy
```

- 首次构建约 15~30 分钟（5 个后端 Maven 构建 + 2 个前端 npm 构建，有缓存显著加速）
- MySQL 首次启动按序执行 `deploy/mysql/init/01~07`（含 dev 种子：config_json 指向内置 Mock——

### 7.3 端口与环境变量

宿主端口（括号内为 dev 占用，便于区分）：前端同域 **8088**(80)、网关 **8180**(8080)、
MySQL **3317**(3307)、Redis **6380**(6379)、MinIO **9010/9011**(9000/9001)、Nacos **8858/9858**(8848/9848)、
RocketMQ namesrv **9886**(9876)、契约 Mock **8099**。

| 变量 | 默认（仅供本机测试） | 说明 |
|---|---|---|
| CHANNEL_SSO_MOCK | false | test/prod 必须 false |
| SECRET_STORE_KEY | dev 默认值 | config_json ENC 密文主密钥；生产必须覆盖 |
| CHANNEL_LS_BASE_URL | http://contract-mock:8099 | verify 地址 base（不含路径）；接真实环境改为创金零售给的地址 |
| CHANNEL_LS_APP_KEY | demandhub-test | 服务间鉴权 app_key（按环境独立） |
| CHANNEL_LS_APP_SECRET | 占位值 | **真实值只经环境注入，不入仓库、不入日志** |
| CHANNEL_LS_TICKET_TTL / TIMEOUT_MS | 60 / 3000 | 票据 TTL 秒 / verify 超时毫秒 |

```bash
$env:CHANNEL_LS_BASE_URL="http://<创金零售测试地址>"; $env:CHANNEL_LS_APP_KEY="<app_key>"; $env:CHANNEL_LS_APP_SECRET="<app_secret>"
docker compose -f deploy/docker-compose.test.yml up -d system contract-mock   # 仅重启 system（contract-mock 可停用）
```
